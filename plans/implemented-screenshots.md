# Screenshot implementation

Owned source: `crates/desktop/src/rune_shot.rs`. No editor, annotation, UI or utility source was edited by this agent.

- F02: keep the original annotation actor, frozen image, selection and undo state until delivery succeeds. Save/clipboard/spawn failures remain visible in the overlay. Retry Save re-renders that actor; Save elsewhere opens a native destination picker and preserves no-clobber publication. Concurrent replacement, closing and mutation are blocked during delivery or a destination dialog. New captures cannot replace an existing capture.
- F04: Copy performs clipboard delivery directly, without creating folders, encoding a file, adding a library entry or requiring writable storage. Its success message explicitly says no file was saved. Save and Edit remain explicit disk actions.
- F21: Shot owns the delivery JoinHandle, polls and joins it before handling the result, and joins outstanding work on Drop. The worker performs no UI callbacks, so joining does not require a live UI event loop. Failed delivery keeps its session. `pub fn shutdown_blocked() -> bool` reports any open frozen capture, including delivery and failed-save recovery. Parent must OR this into the main app's quit and update/restart guards. Guarding open captures also protects a still-unsaved selection. `busy(&Shot)` identifies delivery/dialog work inside the overlay. Crash/power-loss recovery remains outside this in-memory fix.
- F17 region scope: arrows create/move a selection; Alt+arrows resize; Shift increases movement to 10 monitor pixels. Bounds and minimum size are enforced. On-screen instructions and an accessible region-size label describe the keys. Annotation geometry belongs to the separate annotation owner.
- F09 integration API: `begin_for_utility(&OverlayHandle<Shot>, Frame, PathBuf, complete)` accepts a `FnOnce(&mut AppState, PathBuf) -> Result<(), String> + Send + 'static`. Parent's utility capture route must call this instead of `begin`, capture the originating tool/session identity and validate it in `complete` before appending the returned saved path exactly once. Save is labeled Use capture in this mode. Copy remains clipboard-only; Edit explicitly opens the editor. Cancelling reports that no utility input was added. A callback rejection leaves the saved image in place and reports its exact path, so a vanished origin cannot silently receive a new input. The callback is consumed only after successful file delivery and runs on the main application thread. Begin attempts during an existing session are refused and do not overwrite it. Parent should not retain a separate unresolved capture-pending flag on cancellation, since this API only invokes completion for successful file delivery.

Validation performed: read pinned Rune `on_press_tx` and file-dialog APIs, annotation AcceptRegion behavior and shared no-clobber image publication; ran standalone rustfmt and scoped git diff --check. Added four unit tests for clipboard success/failure without disk operations, annotated-frame retry after an existing-file save failure, bounded keyboard geometry, and owned-worker joining on Drop. No local compilation, cargo tests/builds, runtime capture, clipboard or native UI execution. Boat must compile and run the tests centrally; Windows still needs native dialog, focus/keyboard, clipboard and slow-save shutdown acceptance.
