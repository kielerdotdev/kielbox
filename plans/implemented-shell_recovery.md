# Shell and recovery implementation

Implemented in the assigned shell files only. No commits or subagents.

- F06: Library and Settings tray IDs select the named page and reopen the window. Tray quit and window-close quit use the shared shutdown gate.
- F08: preference persistence returns success, rolls back the complete live preference snapshot on failure, and retains the save error. Capture-folder root changes happen only after persistence. Shortcut changes restore the previous runtime registration on startup, registration or persistence failure. Preference publication syncs the temporary file before replacement.
- F12: installation startup retains its resolved State. Installed first run opens Storage with setup guidance; Use existing data invokes the existing remember_working_directory API. The selected workspace activates on the next launch; existing data is never moved, merged or overwritten. Storage displays the current workspace. Portable selection remains the existing --working-directory CLI route because its installation API deliberately owns no bootstrap selection.
- F13/F22: Library renders pages of 100 matching files, with explicit shown/total counts and Previous/Next. Search/filter and thumbnail admission share the same matches and clamped page offset, including files beyond the old 500-item boundary. Thumbnail queues remove off-page work even when no new paths are admitted.
- F15: Library Trash and palette Trash recovery read existing versioned recovery.json journals after restart or toast expiry. Journal size, version, batch containment, source containment and symlink boundaries are checked. Restored entries disappear by checking actual remaining destinations. Existing original files cause a visible failure and remain untouched; no-clobber restore is preserved. A corrupt journal reports its error and is preserved for manual recovery.
- F19: shortcut fields have unique action accessibility names, independent Not set placeholders, per-row registration details and Not applied draft status. Failed registration rejects the candidate rather than announcing success.
- F20: explicit NoticeKind controls severity/lifetime. Declared successful job variants can expire; unknown legacy direct-string producers conservatively remain persistent. Independent worker outcomes queue behind the displayed notice, and prior observed errors are retained if legacy producers replace them. Error wording is never inspected to determine severity. The public notify(kind, message) API is available to collaborators for complete typed producer migration.

Integrated collaborator APIs: tray.update_quick_state(capture.quick_tray_state(), &preferences.hotkeys[6]) immediately before tray.update; rune_shot::shutdown_blocked() in quit/restart/update safety; rune_editor::prepare_to_leave() for shell file replacement and shutdown. This starts and waits for annotation recovery acknowledgements and retains editor errors. Capture status also blocks quit/update during native capture, quick startup/recording/pause/finishing and pending saves. Shared Settings audio flags are disabled and callback-guarded while either recorder is busy. The blocking message explicitly says Finish or Cancel capture. Automatic update polling receives the same conservative capture/image safety state.

Regression tests added for filtered old-file paging and clamping, visible thumbnail admission and stale-queue removal, explicit notice severity/queued outcomes, injected preference-write rollback, and journal recovery across session loss and restore collisions. Existing preference atomic-write tests remain in place.

Validation performed: standalone rustfmt parsed owned Rust files, and git diff --check passed. No Rust compilation, cargo builds/tests, FFmpeg, native capture, browser or heavy local execution was performed. Tests are authored but NOT executed. Central Boat validation must compile the integrated Windows and headless paths and run these regressions. Native acceptance still needs tray navigation/minimized indicators, occupied hotkeys, unwritable preferences, restart into an existing workspace, screenshot cancellation/recovery during quit/update, and Trash restore after restart.
