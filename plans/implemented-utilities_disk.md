# Utilities and disk implementation

Owned changes: `crates/desktop/src/rune_tools.rs`, `crates/toolkit/src/utilities.rs`.

- F09: Capture region uses the screenshot agent's `rune_shot::begin_for_utility(handle, frame, folder, callback)` API. The callback checks the originating utility ticket, supplies the reviewed saved capture as input and starts that tool instead of opening the image editor. This primary path deliberately retains the explicitly saved screenshot. Without the Rune overlay, selection feeds captured pixels directly to a utility worker without publishing an image file.
- Additional integration API: `State::capture_ticket() -> (u64, util::Tool)` and `State::accept_capture(ticket, Frame, rune::Waker) -> bool` support an ephemeral pixel callback. `utilities::run_with_frame(Request, Option<Frame>, &CancelToken)` shares the existing backend implementation. No other Rune files were edited by this work.
- F10/F11: All 17 tools now render task-appropriate inputs/options using existing controls. Folder index and Split use folder dialogs; Split defaults to 2×2; hash comparison defaults blank; video thumbnail defaults to second 0 at maximum width 1024px. Effects, orientation, index formats and MP4/WebM/GIF are selectable. Relevant units/ranges are displayed. Combine inputs can move up to set order.
- F14: Tool changes/close cancel and detach the old receiver; new runs clear prior results before validation. Dialog callbacks check generation/tool. Save operations advance generation, preventing older dialogs from saving a different result. Output paths enter the result only after successful no-clobber publication.
- F24: Explicit image/text clipboard actions, image save filters for PNG/JPEG/WebP/BMP, report save, and Reveal/Copy path for generated/saved outputs. Removed unsupported pin/borderless/screen-sampling claims from backend descriptions. Image tools no longer show ignored destination controls.
- F13/F23: 100-entry disk pages expose every scanned child with shown/total counts; breadcrumbs and Up reset paging. Every entry, current folder and sampled error has Reveal/Copy path. Persistent details show backend, fallback, elapsed time, files/folders, errors/skips, partial totals and logical-size/hard-link/sparse accounting. Error details scroll independently. Disk remains read-only.

Validation: rustfmt completed and scoped `git diff --check` passed. No Rust compilation, cargo commands, native dialogs, clipboard operations or runtime tests were executed locally. Added targeted unrun tests for task defaults/ticket invalidation, ephemeral frame input and no-clobber text saves. Existing utility tests remain in place. Central Boat validation should run toolkit utility tests and desktop tests, then Windows acceptance for all forms, 501-child paging, capture callback ownership, stale dialogs, save failures and each output format.
