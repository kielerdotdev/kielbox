# Default desktop-audio recovery — 2026-11-05

Scope: native Windows game-capture audio workers in `windows-capture`. Only a System track without an explicit endpoint follows the Windows default **console render** endpoint. Explicit endpoints, microphone tracks and per-process audio never switch to another source. The independent recording-tools/screencast audio backend is outside this change.

The worker attempts to register an `IMMNotificationClient` before opening its initial default endpoint. If optional registration fails, capture continues on the current endpoint with an actionable notice; typed invalidation recovery remains enabled. The callback increments an atomic generation only for console render changes; it never activates devices, reads endpoint IDs or waits on a lock. The owning worker notices a generation change or the typed WASAPI `DEVICE_INVALIDATED` / `RESOURCES_INVALIDATED` errors, closes its old client, then attempts to reopen the current default endpoint. Other read failures, including queue overflow and access/format errors, remain terminal.

Recovery allows three reopen attempts **total per recording**, with a 100 ms cancellable pause before each and a five-second elapsed retry-scheduling window for an incident. Cancellation is checked before and after activation. This does not impose a hard timeout on synchronous Windows COM/driver calls; a driver that hangs inside activation, stop or interface release remains a limitation. There are no detached recovery threads.

Reopened sources retain the original recording QPC epoch. Overlapping first samples are trimmed rather than duplicated, and positive timestamp gaps remain gaps. No silence is fabricated or timestamp reset used to hide missing audio. A discontinuity is counted and bounded recovery/recovered notices reach the UI independently of the PCM queue. Terminal failure has separate storage and is delivered after pending notices, so a full PCM queue or a preceding recovery notice cannot suppress it. Failure asks the user to restore/reselect their source and restart recording.

Pure injected tests cover routing, typed failure classification, notification role filtering, original epoch propagation, stale-generation reads, PCM overlap values and positive gaps, release-before-open ownership, retry count/window, cancellation around activation, and bounded notices plus terminal failures when PCM is full. These tests do not activate microphones, remove hardware or change Windows defaults. Actual unplug/default-switch behavior is not claimed from injected events.
