## Cancellation and recovery details

Library catalog work carries no thumbnail-page generation, so browsing pages does not throw away metadata discovery. Thumbnail work carries both catalog and page generations. An old completion is rejected before it can remove a newer request with the same path. A worker acknowledgment can trigger retry of a rejected admission; polling without new progress does not continuously repaint. Leaving Library also cancels stale thumbnail work, while a later Capture preview is admitted under the current generation.

FFprobe/FFmpeg cancellation uses the existing worker cancellation closure. An image decoder operation already inside a non-interruptible library call can finish before cancellation is observed; this change does not promise immediate preemption of every decoder. Global catalog invalidation and shutdown still cancel all related work.

Export output is a job result rather than a property of the current preview generation. Successful late completion now survives navigation. The receipt remains an Editor notification; a persistent global export job center is still separate work. Existing explicit failure/recovery behavior is retained rather than reporting a failed earlier job as a successful current clip export.

The Library query cache retains exactly one key/result, never a history of searches. Its key covers source paths/order, catalog revision, favorites, custom display names, filter, sort, and normalized search. Catalog invalidation and completed catalog publication both clear it. Source and preference content equality deliberately catches direct mutation, import/rename, and preference restoration without relying on allocation identity or incomplete notification hooks. Hits still perform linear content comparisons; this is not an O(1) query-cache claim. Misses retain the existing filtering/sorting semantics. Immutable watch snapshots use the same results as Library and editor queue synchronization, so memoization cannot silently choose a different queue order.

E3 adds one dedicated CPU query worker with one replaceable pending input and one result slot. Inputs retain the immutable catalog by `Arc`; submission copies source/preference values once per miss but never clones the full metadata map. Filtering, stable index merge sorting, name-key computation, byte totals, watch paths, and all five category counts execute on the worker. Cancellation is checked during scanning, sorting, and result assembly. Atomic generations guard publication, and obsolete input/result slots are replaced rather than queued. Leaving Library/Editor or dropping Library cancels work; worker joining is transferred off the UI thread.

While a current result is unavailable, Library paints an explicit updating state and exposes no cards/watch queue from the previous query. Watch clicks from an old painted frame recheck the current result. Catalog publication and query completion use existing polling to synchronize the editor queue. Worker computation panics become an error with Retry view; thread creation failure explains that rcr must be restarted. The hidden input proof explicitly allows the real worker to finish between assertions; production rendering never waits on query completion.

## Prioritized execution roadmap

1. **Measure painted-frame responsiveness and reduce cold admission copies.** E3 worker regressions and the CPU benchmark passed. Next validate total p95 frame/update time and repeated cold admission under realistic typing/navigation. A narrow safe candidate is reusing the previous input's immutable source `Arc` after exact content equality when only search/filter/sort/catalog inputs change; this avoids deep-cloning unchanged paths without introducing fragile revision hooks. Sharing preference maps would require a separate ownership change and benchmarks. If linear equality remains material, introduce explicit immutable source/preference revisions with exhaustive mutation coverage; do not replace safe checks with pointer identity. No such follow-up source change is included here.
2. **Make export jobs and receipts visible across Studio.** Keep job identity, source title, destination, progress, cancellation, and completion outside the active Editor view. Show completed jobs from Library/Capture as well as Editor. Cover navigation during export, late success/failure, cancellation, and replacement of the current source. The current fix prevents loss but is not a global job center.
3. **Add local watch collections and session grouping.** Start with durable local queues/favorites, clear game/date/session headings, and optional bookmarks. Preserve the active filtered order, current clip, and playback position when returning from editing. Validate rapid navigation, missing items, long queues, and screen-share-friendly layouts at 900×600 and 1440×900. Remote synchronization, accounts, and hosting require a separately agreed product/backend scope.
4. **Provide explicit Locate source recovery.** Explain a missing/moved file and let the user select its replacement. Validate source identity/duration, retain original sidecar and recoverable backup, and avoid overwriting either file until the user commits. Exercise offline drives, renamed clips, incompatible replacements, and undoable recovery.
5. **Add a focused quick-trim workflow.** Offer a small in/out range and separate output before advanced editing. Keep viewing, edits, and exports distinguishable. Preserve the existing conservative native-audio eligibility and external fallback until new trim paths pass waveform/timestamp parity; do not hide seek latency by changing project FPS or sample alignment.

For every phase: preserve source bytes and export semantics, verify Undo/Redo equality for watch-only actions, reject stale worker publication, test error→Next recovery, and run the hidden native interaction proof. Use generated media and temporary profiles; never use a live game capture or physical audio endpoint merely to validate the editor.
